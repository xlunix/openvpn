# Документация по скриптам проекта OpenVPN + bee2evp

Эта папка содержит скрипты для автоматизации настройки, запуска и тестирования OpenVPN с поддержкой белорусских криптографических алгоритмов через bee2evp engine.

## Обзор скриптов

Скрипты разделены на три категории:

1. **Скрипты настройки и запуска** - подготовка окружения и запуск сервисов
2. **Скрипты тестирования** - проверка работоспособности VPN соединения
3. **Скрипты диагностики** - проверка состояния системы

## Скрипты настройки и запуска

### 1. setup-ca.sh

**Суть:** Генерирует все необходимые криптографические ключи и сертификаты для работы OpenVPN.

**Зачем нужен:**
- Создает центр сертификации (CA) для подписи сертификатов
- Генерирует ключи и сертификаты для сервера и клиента
- Создает параметры Диффи-Хеллмана для обмена ключами
- Генерирует TLS ключ для дополнительной защиты (опционально)

**Где используется:**
- Автоматически вызывается из `start-server.sh` и `start-client.sh`, если ключи отсутствуют
- Может быть запущен вручную для пересоздания ключей

**Когда запускается:**
- При первом запуске системы (ключи отсутствуют)
- При необходимости пересоздания ключей

**Настройка через переменные окружения:**

Скрипт поддерживает настройку значений сертификатов через переменные окружения:

```bash
# Географические данные
export CERT_COUNTRY=BY          # Страна (ISO 3166-1 alpha-2)
export CERT_STATE=Minsk         # Регион/Область
export CERT_CITY=Minsk          # Город
export CERT_ORG=YourCompany      # Название организации

# Настройки для CA
export CERT_OU_CA=IT            # Подразделение CA
export CERT_CN_CA=YourCompany-CA # Имя CA сертификата

# Настройки для сервера
export CERT_OU_SERVER=Server     # Подразделение сервера
export CERT_CN_SERVER=vpn-server # Имя серверного сертификата

# Настройки для клиента
export CERT_OU_CLIENT=Client     # Подразделение клиента
export CERT_CN_CLIENT=vpn-client # Имя клиентского сертификата
```

По умолчанию используются тестовые значения (`TestVPN`), которые подходят для тестовой инфраструктуры.

**Особенности:**
- Создает сертификаты с правильными расширениями для OpenSSL 3.x:
  - CA сертификат: `basicConstraints=CA:TRUE`, `keyUsage=keyCertSign, cRLSign`
  - Серверный сертификат: `extendedKeyUsage=serverAuth`, `keyUsage=digitalSignature, keyEncipherment`
  - Клиентский сертификат: `extendedKeyUsage=clientAuth`, `keyUsage=digitalSignature`
- Генерирует ключи в директориях `/etc/openvpn/keys/` и `/etc/openvpn/ca/`
- Использует RSA 2048 бит для всех ключей
- Срок действия сертификатов: 3650 дней (10 лет)

### 2. start-server.sh

**Суть:** Запускает OpenVPN сервер с правильной конфигурацией окружения.

**Что делает:**
1. Настраивает переменные окружения:
   - `LD_LIBRARY_PATH` - путь к библиотекам bee2 и bee2evp
   - `OPENSSL_CONF` - путь к конфигурации OpenSSL с bee2evp
2. Проверяет наличие конфигурационного файла `/etc/openvpn/server.conf`
3. Создает директории для логов
4. Проверяет наличие ключей и запускает `setup-ca.sh` при необходимости
5. Создает TUN интерфейс для VPN
6. **Создает симлинк для bee2evp engine** - чтобы OpenSSL мог найти engine в системной директории
7. Запускает OpenVPN сервер

**Особенности:**
- Автоматически создает симлинк `/usr/lib/x86_64-linux-gnu/engines-3/bee2evp.so` → `/build/build/install/lib/libbee2evp.so`
- Это необходимо для работы bee2evp engine с OpenSSL 3.x
- Использует `exec` для замены процесса оболочки на OpenVPN

**Использование:**
```bash
/scripts/start-server.sh
```

### 3. start-client.sh

**Суть:** Запускает OpenVPN клиент с правильной конфигурацией окружения.

**Что делает:**
1. Настраивает переменные окружения (аналогично серверу)
2. Ждет 5 секунд для запуска сервера
3. Проверяет наличие конфигурационного файла `/etc/openvpn/client.conf`
4. Создает директории для логов
5. Проверяет наличие ключей и запускает `setup-ca.sh` при необходимости
6. Создает TUN интерфейс для VPN
7. **Создает симлинк для bee2evp engine** (аналогично серверу)
8. Запускает OpenVPN клиент

**Особенности:**
- Автоматически создает симлинк для bee2evp engine
- Проверяет наличие всех необходимых ключей (client.key, client.crt, ca.crt)
- Использует `exec` для замены процесса оболочки на OpenVPN

**Использование:**
```bash
/scripts/start-client.sh
```

## Совместимость

Все скрипты работают как в тестовом, так и в продакшн окружении:

- **Тестовое окружение**: Используются дефолтные значения (`TestVPN`) или значения из `.env` файла
- **Продакшн окружение**: Переменные окружения устанавливаются через Docker Compose или `.env` файл

Скрипты автоматически определяют окружение и работают соответствующим образом.

## Переменные окружения

### Для настройки сертификатов

Все переменные имеют значения по умолчанию, поэтому их установка не обязательна:

- `CERT_COUNTRY` - страна (по умолчанию: `BY`)
- `CERT_STATE` - регион (по умолчанию: `Minsk`)
- `CERT_CITY` - город (по умолчанию: `Minsk`)
- `CERT_ORG` - организация (по умолчанию: `TestVPN`)
- `CERT_OU_CA`, `CERT_OU_SERVER`, `CERT_OU_CLIENT` - подразделения
- `CERT_CN_CA`, `CERT_CN_SERVER`, `CERT_CN_CLIENT` - имена сертификатов

### Для работы OpenSSL

- `OPENSSL_CONF` - путь к конфигурации OpenSSL (устанавливается автоматически в скриптах)
- `LD_LIBRARY_PATH` - путь к библиотекам (устанавливается автоматически в скриптах)

## История изменений

### Последние улучшения

- **Поддержка переменных окружения** в `setup-ca.sh`:
  - Все значения сертификатов настраиваются через переменные окружения
  - Значения по умолчанию подходят для тестов
  - Совместимо с продакшн окружением

- **Исправления для OpenSSL 3.x**:
  - Правильные расширения для CA сертификата (`basicConstraints=CA:TRUE`)
  - Правильные расширения для серверных и клиентских сертификатов
  - Использование `openssl x509` для создания сертификатов с расширениями

- **Автоматическое создание симлинка для bee2evp**:
  - В `start-server.sh` и `start-client.sh` добавлено автоматическое создание симлинка
  - Позволяет OpenSSL находить bee2evp engine в системной директории
  - Необходимо для работы с OpenSSL 3.x

- **Улучшенная логика генерации ключей**:
  - Убрана тестовая логика ожидания ключей из общего volume в `start-client.sh`
  - Скрипты теперь работают одинаково в тестовом и продакшн окружении
  - Проверка наличия всех необходимых ключей перед запуском

## Зависимости

Скрипты требуют:
- OpenSSL (версия 3.x)
- Библиотеки bee2 и bee2evp (собраны и установлены в `/build/build/install/lib/`)
- Доступ к `/dev/net/tun` для создания TUN интерфейса
- Права на создание файлов в `/etc/openvpn/keys/` и `/etc/openvpn/ca/`

## Использование в Docker

Скрипты монтируются в контейнеры через volume:

```yaml
volumes:
  - ./scripts:/scripts
```

Это означает, что изменения в скриптах применяются сразу, без пересборки образов.

## Отладка

### Проблемы с генерацией ключей

```bash
# Проверьте логи
docker compose logs openvpn-server

# Запустите setup-ca.sh вручную
docker compose exec openvpn-server /scripts/setup-ca.sh
```

### Проблемы с bee2evp

```bash
# Проверьте наличие симлинка
docker compose exec openvpn-server ls -la /usr/lib/x86_64-linux-gnu/engines-3/bee2evp.so

# Проверьте загрузку engine
docker compose exec openvpn-server openssl engine -c -t bee2evp
```

### Проблемы с переменными окружения

```bash
# Проверьте переменные в процессе
docker compose exec openvpn-server sh -c 'pid=$(pgrep -f openvpn | head -1); cat /proc/$pid/environ | tr "\0" "\n" | grep CERT'
```
