# Конфигурация OpenVPN сервера

Эта папка содержит все необходимые файлы для настройки и работы OpenVPN сервера с поддержкой белорусских криптографических алгоритмов через bee2evp engine.

## Структура папки

```
server/
├── server.conf          # Основной конфигурационный файл OpenVPN сервера
├── openssl.cnf          # Конфигурация OpenSSL для использования bee2evp
├── ca/                   # Сертификаты центра сертификации
│   └── ca.crt           # Сертификат CA для проверки клиентов
├── keys/                 # Ключи и сертификаты сервера
│   ├── server.key       # Приватный ключ сервера (секретный!)
│   ├── server.crt       # Сертификат сервера для аутентификации
│   └── dh.pem           # Параметры Диффи-Хеллмана
└── easy-rsa/            # Утилиты для управления ключами (опционально)
```

## Назначение

Эта конфигурация предназначена для:
- Приема подключений от VPN клиентов
- Создания защищенной VPN сети для клиентов
- Использования белорусских криптографических алгоритмов (BELT, BIGN, BASH) через bee2evp
- Маршрутизации трафика между клиентами
- Тестирования и разработки VPN решений

## Основные файлы

### server.conf

Основной конфигурационный файл OpenVPN сервера. Определяет:
- Порт и протокол для приема подключений
- Параметры VPN сети (подсеть, маска)
- Параметры сетевого интерфейса (TUN)
- Алгоритмы шифрования и аутентификации
- Правила маршрутизации для клиентов
- Параметры логирования и безопасности

**Ключевые параметры:**
- `port` - порт для приема подключений (по умолчанию 1194)
- `server` - подсеть VPN (10.8.0.0/24 в тестовой среде)
- `cipher` - алгоритм шифрования
- `auth` - алгоритм аутентификации
- `push` - команды, отправляемые клиентам

### openssl.cnf

Конфигурация OpenSSL для загрузки bee2evp engine. Позволяет:
- Использовать белорусские алгоритмы вместо стандартных OpenSSL
- Настроить путь к библиотеке bee2evp
- Выбрать конкретные алгоритмы для использования

**Важно:** Путь к библиотеке (`dynamic_path`) должен соответствовать реальному расположению `libbee2evp.so` в системе.

## Использование

### Быстрый старт (тестовая среда)

1. Убедитесь, что все файлы на месте:
   ```bash
   ls -la /etc/openvpn/
   # Должны быть: server.conf, openssl.cnf, ca/ca.crt, keys/server.key, keys/server.crt, keys/dh.pem
   ```

2. Запустите OpenVPN сервер:
   ```bash
   openvpn --config /etc/openvpn/server.conf
   ```

3. Проверьте работу:
   ```bash
   ip addr show tun0  # Должен показать IP 10.8.0.1
   netstat -ulnp | grep 1194  # Должен слушать на порту 1194
   ```

### Развертывание в продакшене

#### Шаг 1: Подготовка файлов

1. **Скопируйте конфигурацию:**
   ```bash
   sudo cp server.conf /etc/openvpn/server.conf
   sudo cp openssl.cnf /etc/openvpn/openssl.cnf
   ```

2. **Скопируйте ключи и сертификаты:**
   ```bash
   sudo mkdir -p /etc/openvpn/{ca,keys}
   sudo cp ca/ca.crt /etc/openvpn/ca/
   sudo cp keys/server.key /etc/openvpn/keys/
   sudo cp keys/server.crt /etc/openvpn/keys/
   sudo cp keys/dh.pem /etc/openvpn/keys/
   sudo chmod 600 /etc/openvpn/keys/server.key  # Только для чтения владельцем
   ```

3. **Проверьте путь к bee2evp:**
   ```bash
   # Убедитесь, что путь в openssl.cnf соответствует реальному расположению
   ls -la /build/build/install/lib/libbee2evp.so
   # Или укажите системный путь, если библиотека установлена системно
   ```

#### Шаг 2: Настройка для продакшена

**Измените в `server.conf`:**

1. **Порт (опционально):**
   ```conf
   # Используйте нестандартный порт для безопасности
   port 443
   # Или оставьте стандартный 1194
   ```

2. **VPN подсеть:**
   ```conf
   # Выберите подсеть, не конфликтующую с локальными сетями
   server 10.0.0.0 255.255.255.0
   # Или используйте другую подсеть
   server 172.16.0.0 255.255.0.0
   ```

3. **Протокол:**
   ```conf
   # Для работы через NAT используйте TCP
   proto tcp
   # Или оставьте UDP для лучшей производительности
   ```

4. **Логирование:**
   ```conf
   # Раскомментируйте для сохранения логов
   log /var/log/openvpn/server.log
   status /var/log/openvpn/server-status.log
   ```

5. **Безопасность:**
   ```conf
   # Запуск от непривилегированного пользователя
   user nobody
   group nogroup
   ```

6. **Маршрутизация:**
   ```conf
   # Добавьте маршруты для доступа к внутренним сетям
   push "route 192.168.1.0 255.255.255.0"
   push "route 10.0.0.0 255.0.0.0"
   ```

#### Шаг 3: Настройка файрвола

**UFW (Ubuntu):**
```bash
sudo ufw allow 1194/udp
# Или для TCP
sudo ufw allow 1194/tcp
```

**iptables:**
```bash
# UDP
sudo iptables -A INPUT -p udp --dport 1194 -j ACCEPT
# TCP
sudo iptables -A INPUT -p tcp --dport 1194 -j ACCEPT
```

**Firewalld (CentOS/RHEL):**
```bash
sudo firewall-cmd --add-port=1194/udp --permanent
sudo firewall-cmd --reload
```

#### Шаг 4: Включение IP forwarding

```bash
# Временно
sudo sysctl -w net.ipv4.ip_forward=1

# Постоянно
echo "net.ipv4.ip_forward=1" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

#### Шаг 5: Запуск как сервис

**Systemd (Linux):**
```bash
# Создайте unit файл
sudo nano /etc/systemd/system/openvpn-server.service

[Unit]
Description=OpenVPN Server
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/openvpn --config /etc/openvpn/server.conf
Restart=always
RestartSec=5
User=root
Group=root

[Install]
WantedBy=multi-user.target

# Включите и запустите
sudo systemctl enable openvpn-server
sudo systemctl start openvpn-server
```

## Варианты настройки

### Вариант 1: Минимальная конфигурация

Для быстрого тестирования достаточно:
- `server.conf` с базовыми настройками
- `openssl.cnf` для bee2evp
- Ключи и сертификаты

### Вариант 2: С дополнительной безопасностью

Добавьте в `server.conf`:
```conf
# TLS аутентификация
tls-auth /etc/openvpn/keys/ta.key 0

# Проверка отзыва сертификатов
crl-verify /etc/openvpn/ca/crl.pem

# Ограничение доступа по IP
client-config-dir /etc/openvpn/ccd
```

### Вариант 3: С использованием алгоритмов bee2evp

Измените в `server.conf`:
```conf
# Используйте белорусские алгоритмы напрямую
cipher belt-256-cbc
auth bash256
```

**Примечание:** Убедитесь, что клиенты поддерживают эти алгоритмы.

### Вариант 4: Для работы через NAT/Firewall

```conf
# Используйте TCP вместо UDP
proto tcp

# Укажите внешний IP (если сервер за NAT)
# local 0.0.0.0

# Увеличьте таймауты
keepalive 10 300
```

### Вариант 5: Многосерверная конфигурация

Для нескольких серверов используйте:
```conf
# Разные порты для разных серверов
port 1194  # Сервер 1
# port 1195  # Сервер 2

# Разные подсети
server 10.8.0.0 255.255.255.0  # Сервер 1
# server 10.9.0.0 255.255.255.0  # Сервер 2
```

## Тонкая настройка

### Производительность

1. **Отключите сжатие** (если трафик уже сжат):
   ```conf
   # Удалите или закомментируйте
   # comp-lzo
   ```

2. **Настройте буферы:**
   ```conf
   sndbuf 393216
   rcvbuf 393216
   ```

3. **Используйте UDP** (быстрее TCP):
   ```conf
   proto udp
   ```

4. **Оптимизация для множества клиентов:**
   ```conf
   # Увеличьте лимиты
   max-clients 100
   ```

### Безопасность

1. **Включите проверку отзыва сертификатов:**
   ```conf
   crl-verify /etc/openvpn/ca/crl.pem
   ```

2. **Используйте TLS аутентификацию:**
   ```conf
   tls-auth /etc/openvpn/keys/ta.key 0
   ```

3. **Ограничьте алгоритмы:**
   ```conf
   # Только сильные алгоритмы
   cipher AES-256-GCM
   auth SHA512
   ```

4. **Запуск от непривилегированного пользователя:**
   ```conf
   user nobody
   group nogroup
   ```

5. **Ограничение доступа:**
   ```conf
   # Только определенные клиенты
   client-config-dir /etc/openvpn/ccd
   ```

### Надежность

1. **Логирование для отладки:**
   ```conf
   verb 4
   log /var/log/openvpn/server.log
   status /var/log/openvpn/server-status.log 10
   ```

2. **Автоматический перезапуск:**
   ```conf
   persist-key
   persist-tun
   ```

3. **Мониторинг:**
   ```conf
   # Статус соединений
   status /var/log/openvpn/server-status.log 10
   ```

## Персонализация для продакшена

### 1. Выбор алгоритмов шифрования

**Стандартные OpenSSL:**
```conf
cipher AES-256-CBC
auth SHA256
```

**Белорусские (bee2evp):**
```conf
cipher belt-256-cbc
auth bash256
```

**Современные (если поддерживается):**
```conf
cipher AES-256-GCM
auth SHA512
```

### 2. Настройка маршрутизации

**Базовая VPN сеть:**
```conf
server 10.8.0.0 255.255.255.0
push "route 10.8.0.0 255.255.255.0"
```

**Доступ к внутренним сетям:**
```conf
# Позволить клиентам доступ к внутренней сети
push "route 192.168.1.0 255.255.255.0"
push "route 10.0.0.0 255.0.0.0"
```

**Перенаправление всего трафика:**
```conf
push "redirect-gateway def1"
push "dhcp-option DNS 8.8.8.8"
```

### 3. DNS настройки

```conf
# Используйте корпоративные DNS
push "dhcp-option DNS 192.168.1.1"
push "dhcp-option DNS 8.8.8.8"
push "dhcp-option DOMAIN company.local"
```

### 4. Лимиты и ограничения

```conf
# Максимальное количество клиентов
max-clients 50

# Лимит скорости на клиента (опционально)
# client-config-dir /etc/openvpn/ccd
# В файлах ccd: shaper 1000000  # 1 Mbps
```

### 5. Логирование и мониторинг

```conf

# Сохранение логов
log /var/log/openvpn/server.log

# Ротация логов (настройте logrotate)
```

### 6. Безопасность и аудит

```conf
# Проверка отзыва сертификатов
crl-verify /etc/openvpn/ca/crl.pem

# TLS аутентификация
tls-auth /etc/openvpn/keys/ta.key 0

# Запуск от непривилегированного пользователя
user nobody
group nogroup

# Ограничение доступа
client-config-dir /etc/openvpn/ccd
```

## На что влияют настройки

### `port` - порт сервера
- **Влияет на:** На каком порту сервер принимает подключения
- **Важно:** Должен быть открыт в файрволе
- **Продакшен:** Можно использовать нестандартный порт для безопасности

### `server` - подсеть VPN
- **Влияет на:** Какую подсеть получат клиенты
- **Важно:** Не должна конфликтовать с локальными сетями
- **Влияет на:** Количество доступных IP адресов для клиентов

### `proto` - протокол
- **udp:** Быстрее, меньше накладных расходов, может терять пакеты
- **tcp:** Надежнее, работает лучше через NAT, медленнее
- **Влияет на:** Скорость и надежность соединения

### `cipher` и `auth` - алгоритмы
- **Влияют на:** Безопасность и производительность
- **AES-256-CBC:** Стандартный, хорошо поддерживается
- **belt-256-cbc:** Белорусский стандарт, требует bee2evp
- **Влияет на:** Скорость шифрования и требования к CPU

### `keepalive` - проверка соединения
- **Влияет на:** Обнаружение неактивных клиентов
- **Меньшие значения:** Быстрее обнаруживают проблемы, больше трафика
- **Большие значения:** Меньше трафика, медленнее обнаружение проблем

### `push` - команды клиентам
- **Влияет на:** Настройки, которые получают клиенты
- **Маршруты:** Определяют, какой трафик идет через VPN
- **DNS:** Определяют DNS серверы для клиентов

### `max-clients` - лимит клиентов
- **Влияет на:** Максимальное количество одновременных подключений
- **Важно:** Защищает от перегрузки сервера
- **Влияет на:** Производительность и использование ресурсов

## Устранение проблем

### Проблема: Сервер не принимает подключения

**Проверьте:**
1. Порт открыт в файрволе
2. Сервер запущен и слушает на порту
3. IP forwarding включен
4. TUN интерфейс создан

### Проблема: Клиенты не могут подключиться

**Проверьте:**
1. Сертификаты CA совпадают на клиенте и сервере
2. Порт доступен извне (если сервер за NAT)
3. Протокол (udp/tcp) совпадает на клиенте и сервере

### Проблема: bee2evp не загружается

**Проверьте:**
1. Путь к библиотеке в `openssl.cnf` правильный
2. Библиотека существует и доступна для чтения
3. Переменная `LD_LIBRARY_PATH` установлена

### Проблема: Клиенты не могут общаться друг с другом

**Проверьте:**
1. `client-to-client` не закомментирован (если нужен)
2. Маршрутизация настроена правильно
3. IP forwarding включен на сервере

### Проблема: Медленное соединение

**Попробуйте:**
1. Использовать UDP вместо TCP
2. Отключить сжатие
3. Увеличить размер буферов
4. Проверить нагрузку на сервер

## Мониторинг и управление

### Просмотр статуса

```bash
# Статус соединений
cat /var/log/openvpn/server-status.log

# Логи в реальном времени
tail -f /var/log/openvpn/server.log

# Количество подключенных клиентов
grep "CLIENT_LIST" /var/log/openvpn/server-status.log | wc -l
```

### Управление клиентами

```bash
# Отключить клиента
echo "kill <common-name>" | sudo socat - /var/log/openvpn/server.sock

# Перезагрузить сервер
sudo systemctl restart openvpn-server
```

## Важные замечания

1. **Безопасность ключей:** Файл `server.key` должен быть защищен (chmod 600)
2. **Резервное копирование:** Сохраните копии ключей и сертификатов в безопасном месте
3. **Обновление сертификатов:** Регулярно обновляйте сертификаты перед истечением срока действия
4. **Мониторинг:** Настройте мониторинг статуса соединений для продакшена
5. **Логирование:** В продакшене включите логирование для аудита и отладки
6. **Файрвол:** Убедитесь, что порт открыт в файрволе
7. **IP Forwarding:** Должен быть включен для маршрутизации трафика
8. **Производительность:** Мониторьте нагрузку на сервер при большом количестве клиентов
