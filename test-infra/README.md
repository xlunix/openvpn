# Тестовая инфраструктура OpenVPN

Эта папка содержит все файлы, необходимые для тестирования OpenVPN с поддержкой bee2evp в тестовой ветке.

## Структура

```
test-infra/
├── docker-compose-test.yml  # Docker Compose конфигурация для тестов
├── test-all.sh              # Главный скрипт запуска всех тестов
├── env.example              # Пример файла переменных окружения для тестов
├── config/                  # Тестовые конфигурации VPN
│   ├── server/             # Конфигурация сервера для тестов
│   │   ├── server.conf
│   │   └── openssl.cnf
│   └── client/             # Конфигурация клиента для тестов
│       ├── client.conf
│       └── openssl.cnf
└── scripts/                 # Тестовые скрипты
    └── script_test/        # Скрипты для проверки соединения
        ├── check-status.sh # Проверка статуса системы
        ├── test-ping.sh    # Тест ping через VPN
        ├── run-tests.sh    # Автоматический запуск тестов
        └── ...
```

## Использование

### Запуск тестов

Из корневой директории проекта:

```bash
cd test-infra
./test-all.sh
```

Скрипт `test-all.sh` автоматически:
1. Останавливает существующие контейнеры
2. Пересобирает Docker образы (с `--no-cache` для чистой сборки)
3. Запускает контейнеры
4. Ждет инициализации сервисов (30 секунд)
5. Запускает все проверки и тесты

### Ручной запуск

```bash
cd test-infra
docker compose -f docker-compose-test.yml up -d
sleep 30
docker compose -f docker-compose-test.yml exec -T openvpn-client bash /script_test/test-ping.sh
```

### Проверка статуса системы

```bash
cd test-infra
bash ./scripts/script_test/check-status.sh
```

### Остановка тестовой инфраструктуры

```bash
cd test-infra
docker compose -f docker-compose-test.yml down
```

## Возможности и функции

### Автоматическая генерация ключей

- Ключи и сертификаты генерируются автоматически при первом запуске
- Используется общий Docker volume (`test-keys`, `test-ca`) для синхронизации ключей между сервером и клиентом
- Скрипт `setup-ca.sh` создает самоподписанные сертификаты с правильными расширениями для OpenSSL 3.x

### Проверка статуса системы

Скрипт `check-status.sh` выполняет комплексную проверку:

1. **Проверка контейнеров** - статус сервера и клиента
2. **Проверка сети** - наличие Docker сети vpn-network
3. **Проверка OpenVPN** - наличие и версия OpenVPN в образе
4. **Проверка bee2 и bee2evp** (использует `check-bee2.sh` для детальной проверки):
   - Наличие библиотек (динамических и статических)
   - Проверка линковки bee2evp к bee2
   - Проверка загрузки bee2evp engine через OpenSSL
   - Список доступных алгоритмов
   - Проверка линковки OpenVPN с правильными библиотеками
   - Тест алгоритмов bee2
5. **Проверка OpenSSL**:
   - Версия OpenSSL
   - Наличие конфигурации
   - Настройка bee2evp в конфигурации
   - Проверка переменной окружения OPENSSL_CONF в процессе OpenVPN
6. **Проверка конфигурационных файлов** - наличие всех необходимых конфигов
7. **Проверка скриптов** - наличие и исполняемость скриптов
8. **Проверка логов сервера** - анализ состояния сервера по логам
9. **Проверка VPN соединения** - ping между клиентом и сервером

### Детальная проверка bee2evp

Скрипт `check-bee2.sh` выполняет полную диагностику использования bee2evp:

- Проверяет наличие всех необходимых библиотек
- Проверяет версию и линковку OpenSSL
- Проверяет конфигурацию OpenSSL
- Проверяет загрузку bee2evp engine
- Проверяет линковку OpenVPN с правильными библиотеками
- Тестирует алгоритмы bee2 (belt-hash, belt-cbc)

Скрипт автоматически запускается в `test-all.sh` и может быть запущен вручную:

```bash
# В контейнере
docker compose -f docker-compose-test.yml exec openvpn-server bash /script_test/check-bee2.sh

# Или через test-all.sh (автоматически)
cd test-infra
./test-all.sh
```

Подробная документация: `test-infra/scripts/script_test/CHECK_BEE2.md`

### Переменные окружения

Для настройки сертификатов можно использовать переменные окружения (см. `env.example`):

```bash
# Опционально: скопируйте и настройте
cp env.example .env
# Отредактируйте .env при необходимости
```

По умолчанию используются тестовые значения (`TestVPN`), которые подходят для тестов.

### Healthchecks

Оба контейнера (сервер и клиент) имеют healthchecks:
- **Сервер**: проверяет наличие процесса OpenVPN и TUN интерфейса
- **Клиент**: проверяет наличие процесса OpenVPN, TUN интерфейса и возможность пинговать сервер

## Отличия от продакшн конфигураций

Тестовые конфигурации могут отличаться от продакшн:

1. **IP адреса** - используют тестовую подсеть `10.10.0.0/24` (Docker сеть) и `10.8.0.0/24` (VPN сеть)
2. **Проверка сертификатов** - используют `peer-fingerprint` для работы с самоподписанными сертификатами в OpenSSL 3.x
3. **Настройки для тестирования** - могут содержать дополнительные опции для отладки
4. **Общие volumes** - используют именованные volumes для синхронизации ключей между контейнерами

## Ключи и сертификаты

Ключи и сертификаты **не хранятся** в этой папке. Они генерируются автоматически в контейнерах при первом запуске через скрипт `../scripts/setup-ca.sh`.

Директории `keys/` и `ca/` создаются автоматически в контейнерах и игнорируются git (см. `../.gitignore`).

### Генерация ключей

Скрипт `setup-ca.sh` автоматически:
- Создает CA (Центр сертификации) с правильными расширениями для OpenSSL 3.x
- Генерирует ключи и сертификаты для сервера и клиента
- Создает параметры Диффи-Хеллмана
- Использует переменные окружения для настройки значений сертификатов

## Важно

- Все файлы в этой папке предназначены **только для тестовой ветки**
- Эти файлы не должны попадать в ветки клиента или сервера
- Тестовые конфигурации VPN находятся в `config/` (отдельно от продакшн конфигов)
- Продакшн конфигурации в `../vpn-config/` **не изменяются** тестовой инфраструктурой
- Скрипты запуска используются из `../scripts/` (общие для всех веток)

## Зависимости

Тестовая инфраструктура использует:
- `../Dockerfile` - для сборки образов
- `../vpn-config/` - конфигурации VPN (только для чтения)
- `../scripts/` - скрипты запуска сервера и клиента

## Устранение неполадок

### Контейнеры не запускаются

```bash
# Проверьте логи
docker compose -f docker-compose-test.yml logs

# Пересоберите образы
docker compose -f docker-compose-test.yml build --no-cache
```

### VPN соединение не устанавливается

```bash
# Проверьте логи сервера
docker compose -f docker-compose-test.yml logs openvpn-server

# Проверьте логи клиента
docker compose -f docker-compose-test.yml logs openvpn-client

# Проверьте статус системы
bash ./scripts/script_test/check-status.sh
```

### Проблемы с ключами

```bash
# Удалите volumes с ключами
docker compose -f docker-compose-test.yml down -v

# Запустите заново (ключи сгенерируются автоматически)
./test-all.sh
```
